# Agent Network v0.4 Rancher Security Review Live Validation

## 1. Objective

本次验证以真实 Rancher Security Review 报告为输入，验证 Agent Network v0.4 从 Markdown Claim Extraction 到 Evidence Retrieval、Dual Fact Review、Security/Logic Review 和 Merge 的端到端执行能力。

本报告基于三次真实 Live Run 记录，不代表正式安全审计结论。

## 2. Architecture

```text
Markdown report
  → deterministic Claim Extraction
  → high-value Claim selection
  → offline BM25 Evidence Retrieval
  → Fact A / Fact B
  → Security Agent
  → Logic Agent
  → Merge Agent
```

Live runner 位于 case-local 目录，不修改 v0.4 核心 workflow、Claim schema、provider adapter 或旧 case artifact。

## 3. Workflow

本案例从原始 `input.md` 重新抽取 149 个 Claim，并按确定性规则选择 30 个高价值 Claim，覆盖 Cluster Agent、Reverse Tunnel、ServiceAccount Token、RBAC、Cloud Credential 和 CVE Security 相关主题。

Fact A/B 使用独立 deep-copy context，不共享 reviewer output。Security、Logic 和 Merge 使用 checkpoint runner；每个阶段完成后立即写入 artifact 和运行 metadata。

## 4. Evidence Pipeline

Evidence 仅使用既有本地库：

- Evidence chunks：6,420
- BM25 top-k retrieval
- Retrieval coverage：30/30
- Evidence network requests：0

Fact context 采用 top-2 evidence、每个 chunk 350 字符、每个 Claim 约 900 字符的压缩策略，同时保留 `chunk_id`、`document_id` 和 canonical URL 追溯信息。

## 5. Model Allocation

| Agent | Provider | Model | Planned calls |
|---|---|---|---:|
| Fact A | deepseek_official | deepseek-v4-pro | 6 |
| Fact B | dashscope_official | qwen3.7-plus | 6 |
| Security | siliconflow | Qwen/Qwen3.6-35B-A3B | 1 |
| Logic | siliconflow | deepseek-ai/DeepSeek-V4-Flash | 1 |
| Merge | siliconflow | zai-org/GLM-5.2 | 1 |

目标总调用数为 15。Security、Logic 和 Merge 使用 case-local JSON-only request policy，temperature 为 0；Logic timeout 为 180 秒并配置一次 retry。

## 6. Three Run History

### Run 1

- Fact budget preflight 失败，30 个 Claim 未发起 Fact provider request。
- Fact estimated calls 因输入 context 过大扩展到 36，超过 coordinator budget。
- Security provider 调用成功但返回 `finish_reason=length`、空正文，解析失败。
- Logic 和 Merge 完成。
- 记录的 model calls：3。

### Run 2

- Fact context compression 后恢复 Fact A/B 执行。
- Fact A/B 成功完成。
- Security 仍出现截断/结构化解析失败。
- Logic provider timeout，Merge 未执行。
- checkpoint 和增量 metadata 暴露了中途失败状态。
- 记录的 model calls：13；runtime：约 766 秒。

### Run 3

- Fact A/B 成功：6 + 6 calls。
- Logic 成功：1 call。
- Merge 成功：1 call。
- Security provider 调用完成，但仍为 `parse_failed`，错误为 `truncated_response`。
- 总调用数：15。
- Runtime：895.29 秒。

## 8. Findings

### Context budget importance

完整 evidence context 会导致 Fact budget preflight 拆分 batch，甚至阻止任何 provider request。受限 evidence compression 将 Fact batch 最大输入降至约 7,422 tokens，并恢复 6 + 6 的 planned calls。

### Structured output reliability

Smoke test 能证明 provider 基础 JSON 输出可用，但不能代表长上下文 reviewer 稳定。Security 在三次 live run 中仍出现 reasoning/output truncation 或 `parse_failed`，说明需要持续控制 prompt 大小、response format 和 reasoning 行为。

### Checkpoint necessity

全流程结束后统一写 artifact 会丢失中途已完成结果。增量 checkpoint 保留了 Fact、Security 和 Logic 的实际状态，使 timeout、parse failure 和 incomplete Merge 可追踪。

当前结果证明了离线 evidence pipeline、Fact A/B 独立执行、成本 preflight 和 checkpoint workflow；Security Agent 的结构化输出稳定性仍是后续 live validation 的主要限制。
