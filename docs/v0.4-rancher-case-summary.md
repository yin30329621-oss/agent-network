# Agent Network v0.4 Rancher Security Review Case

## 1. Case Goal

This case uses Agent Network to perform an evidence-driven review of a Rancher
security technology report. The goal is to separate extractable technical
claims from conclusions that can be supported by authoritative documentation
or source code.

## 2. Input

The input is the Rancher security report at
`cases/rancher-security-review-v1/input.md`.

The case performs:

- Markdown report claim extraction;
- canonical Claim selection and refinement;
- verification of technical facts against official evidence.

The report is treated as the claim source, not as evidence.

## 3. Evidence Sources

The evidence library uses:

- Rancher Official Documentation;
- Rancher Source Code;
- Kubernetes Official Documentation.

Each evidence chunk retains a stable `chunk_id`, source type, document path,
and canonical source URL where available.

## 4. Verification Workflow

```text
Report
  ↓
Claim Extraction
  ↓
Canonical Claim
  ↓
Evidence Retrieval
  ↓
Evidence Decision
  ↓
Revision Suggestions
```

### Multi-Agent Workflow

The complete Agent Network architecture retains the four-agent workflow:

- **Fact Agent** — evaluates technical claims against the available evidence;
- **Security Agent** — analyzes security-relevant components and controls;
- **Logic Agent** — checks claim composition, inference, and overstatement;
- **Merge Agent** — merges the independent analysis into the final review result.

### Dual Fact Verification

Fact verification uses two independent reviewers, Fact A and Fact B. They run independently on the same Claim and evidence context, do not share conclusions or reviewer output, and are reconciled locally after both results are available. Reconciliation summarizes agreement, disagreement, unavailable reviewers, and manual-review requirements.

### Security Agent Scope

The Security Agent focuses on security-relevant areas including:

- Cluster Agent;
- Reverse Tunnel;
- RBAC;
- ServiceAccount Token;
- Credential Management;
- CVE and security controls.

### Logic Agent Scope

The Logic Agent checks for:

- composite Claims containing multiple propositions;
- implicit inference not established by the cited evidence;
- overstatement, including conclusions broader than the source material.

## 6. Main Findings

The review identified several recurring issues:

- composite Claims combining multiple independently verifiable facts;
- broad descriptions containing hidden qualifiers or security conclusions;
- insufficient direct binding between a Claim and a supporting evidence excerpt;
- a need for Revision Suggestions before final technical approval.

Evidence retrieval was complete, but the deterministic EvidenceDecision layer
did not upgrade any Claim to `verified_supported`. Retrieved evidence should
therefore be treated as review candidates until a human confirms the complete
statement and its scope.

## 7. Current Limitation

- EvidenceDecision is intentionally conservative and does not equate BM25
  relevance with factual support.
- Some security semantics, version applicability, and implicit inference still
  require human confirmation.
- This case does not replace a formal security audit, penetration test, or
  product security assessment.
